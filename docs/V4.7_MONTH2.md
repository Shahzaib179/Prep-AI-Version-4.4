# Prep AI v4.7 – Month 2 and the Supabase speed fix

No new Python packages. Database changes (migration 8) apply automatically on start.

## 1. Why the app felt slow on Supabase, and what changed
Every click re-runs the whole page. With a local SQLite file a query costs ~0.1 ms; with Supabase each query is a network round trip (20–150 ms), and a page was making 8–27 of them. On top of that, every query paid an extra connection health check and every read opened its own transaction.

Fixes (all in `db_core.py`):
- No health check on every checkout. A connection used in the last 20 s is trusted; an idle one is probed once.
- Connections run in autocommit; a transaction starts only when something is written.
- A short read cache (`cached_read`, 30 s) for data shown on screen (progress, dashboard, history, classes, bank counts …). It is **cleared the moment this app writes anything**, so a student always sees their own changes immediately. Other users' changes show up within 30 s. Security and deadline checks are never cached.

Measured with `python tests/perf_probe.py` (database round trips for a repeat click): normal pages 8–27 → 0; heavier pages 0–7.

Also worth doing: create the Supabase project in the region closest to Streamlit Cloud (usually a US-East region); every round trip gets shorter.

## 2. Daily Challenge and streak calendar (student → Daily Challenge)
- 5 questions, the same for every student each day (2 Biology, 1 Chemistry, 1 Physics, 1 English), 5 minutes, one attempt per day.
- Questions come from tutor-shared bank questions, then AI, then the built-in starter set, so it always works, even offline.
- Bonus XP: +15 for finishing, +15 more for 5/5. It counts for the streak. Daily leaderboard (score, then speed).
- Streak calendar for the last 5 weeks. (A "streak freeze" is not included.)
- Known limit: the one-attempt rule is applied when the result is saved, so a student who reloads the page mid-challenge can start again.

## 3. Live quizzes (tutor → Live Quiz; student → Live Quiz)
- Tutor picks questions from the bank (or the quiz just created), sets seconds per question and gets a 6-character code.
- Students join, wait in the lobby, and see each question at the same time. Faster correct answers earn up to 1000 points (minimum 500). Options are shuffled per student.
- The server decides everything: when a question is open, who answered, how many points. Late answers are refused (1.5 s grace). Only the host can move the game on.
- Tutor sees the answer bars and top players after each question and a final table with CSV download. After the game each student's answers are added to their normal progress (mistakes, mastery, XP, streak).
- The screens refresh every 2 seconds. Comfortable for a class of 30–60 on the free Supabase tier; for bigger rooms raise `POLL_SEC` in `live_pages.py`.

## 4. WhatsApp reminders (student → Today → 🔔 WhatsApp reminders)
Opt-in only: valid number + a consent tick, off by default, one message per day at most, never after 22:00, nothing sent if there is nothing useful to say (streak about to end, assignment due, revision due, Daily Challenge not done).

How messages are delivered (pick one):
| Option | Cost | Notes |
|---|---|---|
| **Button in the app** ("Send this to myself on WhatsApp") | free | Opens WhatsApp with the text ready; the student presses send. Works with no setup. |
| **Twilio WhatsApp** | free sandbox for testing | In the sandbox each student must first send the join phrase to Twilio's number. Real use needs an approved sender (paid). |
| **Meta WhatsApp Cloud API** | free allowance for replies; messages you start need an approved template and are charged per message in most countries | Set `WA_TEMPLATE_NAME` to a template with one body variable. |

Automatic sending is done by a scheduled job, free on GitHub Actions (`.github/workflows/reminders.yml`, runs hourly):
1. In your GitHub repository: Settings → Secrets and variables → Actions → add `DATABASE_URL` (the same Supabase URL) and `REMINDER_PROVIDER` (`dry_run` to test, then `twilio` or `cloudapi`).
2. For Twilio add `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_WHATSAPP_FROM` (e.g. `+14155238886`). For Cloud API add `WA_CLOUD_TOKEN`, `WA_PHONE_NUMBER_ID`, `WA_TEMPLATE_NAME`.
3. Actions → reminders → Run workflow. Start with `dry_run`: the message is only logged (table `reminder_log`).
You can also run it by hand: `DATABASE_URL=... REMINDER_PROVIDER=dry_run python scripts/send_reminders.py`.
A student turns reminders off in the same panel (there is no "reply STOP" handling).

## 5. The AI test set (tutor → AI Quality, and `scripts/run_ai_eval.py`)
A fixed, hand-checked set in `evals/`: 40 MCQs (Biology, Chemistry, Physics, English, Logical Reasoning) and 6 source passages with 18 questions (12 answerable, 6 whose answer is not in the passage).
Three checks against the real Groq models and the app's real prompts:
- **Solver**: the model answers the 40 questions (target ≥ 85 %).
- **Generate**: the Assessment agent writes MCQs from each passage; we measure valid structure (≥ 90 %), whether a second blind call agrees with the answer key (≥ 80 %), and whether the question is grounded in the passage (≥ 70 %).
- **Grounded**: the tutor must contain the fact when it is in the passage and say so when it is not (≥ 75 %).
Run it after changing a prompt or switching a model: `python scripts/run_ai_eval.py --save`. It writes `ai_eval_report.md`, flags metrics that dropped since the last run, and exits with an error if a target is missed. Saved runs show on the tutor's **AI Quality** tab. The same tab can add the 40 questions to a tutor's question bank as a starter pack.
Note: the "grounded" abstention check looks for phrases like "not available in the provided material", so it is a good indicator, not a proof.
